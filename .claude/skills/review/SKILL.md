# /review — Code Review

Проведи полный code review текущих изменений.

## Шаги

1. **Получить список изменений:**
   ```bash
   git diff --stat
   git diff
   ```

2. **Проанализировать каждый файл** по чеклисту:

### PHP файлы
- [ ] Экранирование вывода: `esc_html()`, `esc_url()`, `esc_attr()`
- [ ] Подготовленные SQL-запросы: `$wpdb->prepare()`
- [ ] Nonce-проверки для форм: `wp_nonce_field()`, `wp_verify_nonce()`
- [ ] Правильные хуки WordPress: `add_action()`, `add_filter()`
- [ ] Функции начинаются с префикса `ovklife_`
- [ ] Text domain `'ovklife'` для всех строк
- [ ] `defined( 'ABSPATH' ) || exit;` в начале файла

### JavaScript файлы
- [ ] Нет `console.log()` (только `console.warn`/`console.error`)
- [ ] `const` вместо `var`/`let` где возможно
- [ ] Обработка ошибок

### CSS файлы
- [ ] Tailwind-классы (не инлайн стили)
- [ ] Нет `text-[13px]` (используй `text-sm`)
- [ ] Нет `!important` без веской причины

### Общее
- [ ] Файлы < 300 строк
- [ ] Нет закомментированного кода
- [ ] Комментарии на русском языке
- [ ] Нет секретов (пароли, ключи)

3. **Вынести вердикт:**

| Категория       | Оценка (1-5) |
|-----------------|--------------|
| Безопасность    | X            |
| Качество кода   | X            |
| Читаемость      | X            |
| WordPress стандарты | X        |
| **Итого**       | **X.X**      |

4. **Список замечаний** (если есть) с конкретными файлами и строками.

5. **Рекомендации** по улучшению (если есть).
